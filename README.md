# ميزان — Mizan Agent

وكيل ذكاء اصطناعي عام يعمل من المتصفح والجوال عبر **واجهة محادثة واحدة**. يكتب المستخدم طلبه بحرية،
ويحدد الوكيل نوع المهمة تلقائياً (سؤال عام، قراءة رابط، تحليل مستند، كتابة كود) وينفذها أو يطلب المعلومات
الناقصة. لا توجد تبويبات ولا شريط جانبي — تجربة واحدة متصلة على غرار Manus.

| القدرة                                      | الحالة               | ملاحظات                                          |
| ------------------------------------------- | -------------------- | ------------------------------------------------ |

> عند إضافة مفتاح حقيقي، تحقق من أول رد قبل الاعتماد عليه.

## التشغيل المحلي

### المتطلبات

- Node.js 20 أو أحدث
- PostgreSQL 14 أو أحدث (أو Docker)
- Docker (اختياري — مطلوب فقط لتشغيل الكود داخل Sandbox)

### الخطوات

```bash
# 1) تثبيت التبعيات
npm install

# 2) إعداد البيئة
cp .env.example .env
```

ولّد مفتاح جلسات واضبطه في `.env` عند `AUTH_SECRET`:

```bash
openssl rand -base64 48
```

```bash
# 3) تشغيل قاعدة البيانات (إن لم تكن لديك واحدة)
docker compose up -d db

# 4) إنشاء الجداول
npm run db:push        # للتطوير السريع
# أو: npx prisma migrate deploy   # لتطبيق الهجرة الجاهزة في prisma/migrations

# 5) التشغيل
npm run dev
```

افتح <http://localhost:3000> ثم أنشئ حساباً من `/register`.

### تشغيل الوكيل بنموذج حقيقي

بدون مفتاح، يعمل التطبيق بمزوّد `mock` الذي يعرض مخرجات الأدوات كما هي بلا لغة طبيعية. لتفعيل نموذج حقيقي:

```env
LLM_PROVIDER="anthropic"
ANTHROPIC_API_KEY="sk-ant-..."
ANTHROPIC_MODEL="claude-sonnet-4-5"
```

> المفاتيح تُقرأ على الخادم فقط. لا يوجد أي مفتاح في حزمة الواجهة — لا تستخدم `NEXT_PUBLIC_` لأي مفتاح.

### تفعيل تشغيل الكود (Sandbox)

```bash
# 1) ابنِ صورة الحاوية المعزولة
npm run sandbox:build

# 2) فعّلها في .env
#    SANDBOX_ENABLED="true"

# 3) أعد تشغيل الخادم
```

إن كان `SANDBOX_ENABLED=false` أو كان Docker غير متاح، يُرفض التشغيل برسالة واضحة.
**لا يوجد مسار بديل ينفّذ الكود على الخادم الأساسي.**

### تفعيل المتصفح التفاعلي (اختياري)

```bash
npm install playwright && npx playwright install chromium
# ثم في .env: PLAYWRIGHT_ENABLED="true"
```

## كيف يعمل الوكيل

```
رسالة المستخدم
      │
      ▼
agent-router  ── يحدد النوع: conversation | web_research | coding
      │            document_analysis | clarification | confirmation_required
      ▼
prompt        ── تعليمات النظام + تلميح التوجيه
      │
      ▼
llm           ── النموذج يقرر: رد نصي أم استدعاء أداة
      │
      ├── read_public_url ─────────► web-reader (فحص SSRF ← fetch ← استخراج نص)
      ├── extract_document_text ──► نص المرفق المستخرج عند الرفع
      ├── generate_code / write_project_file ─► حفظ ملفات المشروع
      ├── list_project_files
      ├── run_code_sandboxed ─────► sandbox (Docker معزول أو رفض صريح)
      └── request_user_confirmation ─► سجل موافقات + بطاقة في الواجهة
      │
      ▼
نتيجة الأداة تعود إلى النموذج كما هي (نجاحاً أو فشلاً)
      │
      ▼
الرد النهائي + المصادر + خطوات التنفيذ  ← يُحفظ في قاعدة البيانات
```

### قواعد الصدق المفروضة

- نتائج الأدوات تعود إلى النموذج **حرفياً**، ونصّ تعليمات النظام يمنع ادعاء نتائج لم تصل.
- كل رد يحمل في `metadata` سجل الأدوات التي نُفِّذت فعلاً، وتعرضه الواجهة تحت «خطوات التنفيذ».
- المصادر المعروضة تحت الرد تأتي من `effects` وليست من نص النموذج — أي أن الرابط المعروض هو
  الرابط الذي قُرئ فعلاً.
- عند فشل أداة يُمرَّر سبب الفشل بلغة واضحة (تسجيل دخول مطلوب، مهلة، حظر SSRF...).

## الأمان

### حماية SSRF (`lib/security.ts`)

كل رابط يمر بفحص قبل أي طلب شبكة، **ويُعاد الفحص عند كل إعادة توجيه**:

- البروتوكولات: `http` و `https` فقط.
- المنافذ: `80`, `443`, `8080`, `8443` فقط.
- ممنوع: `localhost`, `127.0.0.0/8`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16` (بيانات وصف
  السحابة), `100.64/10`, `::1`, `fc00::/7`, `fe80::/10`, العناوين المغلفة `::ffff:`, والنطاقات
  المنتهية بـ `.local` و `.internal` و `.localhost`.
- ممنوع: الروابط ذات بيانات الاعتماد (`user:pass@`) والصيغ الرقمية الملتوية (`http://2130706433/`).
- فحص DNS: كل عناوين IP المُعادة للنطاق يجب أن تكون عامة.

### تشغيل الكود

| القيد        | القيمة                                                           |
| ------------ | ---------------------------------------------------------------- |
| الشبكة       | `--network=none`                                                 |
| الذاكرة      | `--memory` + `--memory-swap` (256 ميجابايت افتراضياً)            |
| المعالج      | `--cpus=0.5`                                                     |
| العمليات     | `--pids-limit=128`                                               |
| نظام الملفات | `--read-only` + `tmpfs` بـ `noexec,nosuid`                       |
| المستخدم     | `--user=1000:1000` (غير جذر)                                     |
| الصلاحيات    | `--cap-drop=ALL` + `no-new-privileges`                           |
| حجم الملفات  | `--ulimit=fsize=4MB`                                             |
| المهلة       | 15 ثانية ثم `SIGKILL`                                            |
| المجلدات     | مجلد عمل مؤقت واحد فقط، **يُحذف بعد التنفيذ**                    |
| الأوامر      | قائمة بيضاء: `node`, `npm`, `npx`, `tsc`, `vitest` ولا رموز صدفة |
| السجل        | كل تشغيل يُسجَّل في جدول `executions` بما فيه المرفوض            |

### الموافقات

أي عملية مؤثرة (بريد، نشر، حذف، تغيير إعدادات، تنفيذ إجراء على موقع) تمر عبر
`request_user_confirmation` فتُنشئ سجل موافقة وتظهر بطاقة في المحادثة بها: وصف العملية، ما سيحدث،
زر موافقة، زر إلغاء. **لا ينفّذ التطبيق أي إجراء خارجي تلقائياً في هذه النسخة** حتى بعد الموافقة —
الموافقة تُسجَّل والتنفيذ يبقى خطوة صريحة لاحقة.

### طبقات أخرى

- كلمات المرور: `bcrypt` بـ 12 جولة.
- الجلسات: JWT `HS256` في كوكي `httpOnly` + `SameSite=Lax` + `Secure` في الإنتاج.
- كل استعلام لبيانات المستخدم مشروط بـ `userId` — تحقق منه اختبار عزل مستقل واختبار E2E.
- التحقق من كل المدخلات بـ Zod قبل أي منطق.
- حد معدل لكل مستخدم: محادثة 30/5د، قراءة ويب 30/5د، مستندات 20/10د، تشغيل كود 10/10د.
- ترويسات أمنية: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`.
- محتوى الصفحات والمستندات يُمرَّر إلى النموذج موسوماً كـ **بيانات لا تعليمات** (حماية من حقن التعليمات).
- لا يُعرض `SYSTEM_PROMPT` ولا أي مفتاح في الواجهة.

## واجهات الـ API

كل المسارات تتطلب جلسة صالحة عدا `auth/*`. الردود بصيغة JSON، والأخطاء `{ "error": "..." }`.

| المسار                       | الطريقة      | الوصف                                                                  |
| ---------------------------- | ------------ | ---------------------------------------------------------------------- |
| `/api/auth/register`         | POST         | `{name, email, password}` → إنشاء حساب + جلسة                          |
| `/api/auth/login`            | POST         | `{email, password}` → جلسة                                             |
| `/api/auth/logout`           | POST         | إنهاء الجلسة                                                           |
| `/api/auth/me`               | GET          | المستخدم الحالي أو `null`                                              |
| `/api/chat`                  | POST         | `{conversationId?, message, attachmentIds?}` → رد الوكيل + حفظ الرسائل |
| `/api/conversations`         | GET / POST   | قائمة المحادثات / محادثة جديدة                                         |
| `/api/conversations/:id`     | GET / DELETE | الرسائل والمشاريع والموافقات / حذف نهائي                               |
| `/api/web/read`              | POST         | `{url}` → `{title, content, finalUrl, fetchedWith}`                    |
| `/api/documents/analyze`     | POST         | `multipart`: `file`, `conversationId?`, `question?`, `persist?`        |
| `/api/code/generate`         | POST         | `{conversationId, prompt, projectId?}` → ملفات المشروع                 |
| `/api/code/run`              | POST         | `{projectId, command}` → تنفيذ داخل Sandbox فقط                        |
| `/api/projects/:id/download` | GET          | ملف ZIP للمشروع                                                        |
| `/api/approvals/:id`         | POST         | `{decision: "approve" \| "reject"}`                                    |

أمثلة على الرموز: `401` غير مسجّل، `403` حُظر بـ SSRF، `404` مورد لا يخص المستخدم،
`413` ملف كبير، `415` نوع غير مدعوم، `422` مدخلات/تحليل فاشل، `429` تجاوز الحد، `503` Sandbox غير متاح.

## قاعدة البيانات

`User` → `Conversation` → (`Message`, `Attachment`, `Project`) → (`ProjectFile`, `Execution`)، بالإضافة إلى
`Approval`. كل الجداول مربوطة بـ `userId` مباشرة أو عبر المحادثة، والحذف تتابعي (`onDelete: Cascade`).
المخطط الكامل في [`prisma/schema.prisma`](prisma/schema.prisma).

```bash
npm run db:push      # مزامنة سريعة أثناء التطوير
npm run db:migrate   # إنشاء هجرة جديدة
npx prisma migrate deploy   # تطبيق الهجرات في الإنتاج
```

### منصات الاستضافة (Vercel / Railway / Fly.io)

1. اربط المستودع واضبط متغيرات البيئة (`DATABASE_URL`, `AUTH_SECRET`, `ANTHROPIC_API_KEY`).
2. أمر البناء: `npm run build` (يشغّل `prisma generate` تلقائياً).
3. طبّق الهجرات: `npx prisma migrate deploy`.
4. اضبط `SANDBOX_ENABLED=false` على المنصات التي لا تتيح Docker — سيرفض التطبيق التشغيل بوضوح
   بدل تنفيذ الكود في مكان غير آمن.

### ملاحظة أمنية مهمة عن Sandbox في الإنتاج

تشغيل الكود يحتاج محرك حاويات. **لا تمرر مقبس Docker إلى حاوية التطبيق** — ذلك يعادل منحها صلاحيات
الجذر على المضيف. الخياران الآمنان:

1. تشغيل التطبيق على المضيف مباشرة مع Docker متاح محلياً.
2. وسيط مقبس مقيّد (مثل `docker-socket-proxy`) يسمح بإنشاء الحاويات فقط.

## قرارات معمارية

| القرار                                    | البديل المرفوض          | السبب                                                                                 |
| ----------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------- |
| **مصادقة مخصّصة** (`jose` + `bcrypt`)     | NextAuth                | الاحتياج بسيط (بريد + كلمة مرور)، تبعيات أقل، وقابلية اختبار كاملة بلا محاكاة معقدة   |
| **Prisma**                                | Drizzle                 | نضج أدوات الهجرة والاستوديو، وتوليد أنواع دقيقة للعلاقات المتداخلة المستخدمة هنا      |
| **Tailwind 3**                            | Tailwind 4              | استقرار الإضافات ودعم واسع للخصائص المنطقية (`ps-`/`pe-`) المهمة في RTL               |
| **خطوط النظام**                           | `next/font` من Google   | يعمل البناء بلا إنترنت ولا يوجد طلب لطرف ثالث من متصفح المستخدم                       |
| **OpenAI عبر `fetch`**                    | حزمة `openai`           | تبعية أقل ونفس النتيجة لاستدعاء واحد                                                  |
| **`fetch` أولاً، Playwright اختياري**     | Playwright افتراضياً    | تثبيت المتصفحات ثقيل (~150 ميجابايت) ولا يحتاجه أغلب الصفحات                          |
| **رفض التشغيل عند غياب Docker**           | تنفيذ محلي محدود        | لا يوجد تنفيذ «شبه آمن»؛ الفشل الصريح أأمن من التنفيذ على الخادم                      |
| **الموافقة تُسجَّل ولا تُنفَّذ تلقائياً** | تنفيذ فوري بعد الموافقة | لا توجد في هذه النسخة أي أداة أثر خارجي؛ عند إضافتها سيُربط التنفيذ بالموافقة صراحةً  |
| **حد المعدل في الذاكرة**                  | Redis                   | يكفي لنسخة واحدة؛ عند التوسع الأفقي انقله إلى Redis (نقطة معروفة في `lib/http.ts`)    |
| **`Uint8Array` لـ pdf-parse**             | تمرير `Buffer`          | نسخة pdfjs المدمجة في `pdf-parse` تفشل بـ `bad XRef entry` مع `Buffer` داخل بيئة Next |
| **تخزين النص المستخرج لا الملف**          | حفظ الملف افتراضياً     | يسمح بأسئلة المتابعة على المستند دون الاحتفاظ بالملف الأصلي                           |

## الخصوصية وسياسة الاحتفاظ

- **الملف الأصلي لا يُحفظ على القرص** إلا إذا فعّل المستخدم `persist` صراحةً.
- النص المستخرج يُحفظ في قاعدة البيانات ليتمكن المستخدم من طرح أسئلة متابعة على المستند نفسه،
  ويُحذف نهائياً مع حذف المحادثة.
- الملفات المحفوظة اختيارياً تحمل تاريخ انتهاء وفق `FILE_RETENTION_DAYS` (30 يوماً افتراضياً)،
  وتُحذف من القرص عند حذف المحادثة.
- المستندات تُرسل إلى مزوّد النموذج **فقط** عند طلب تحليل يخصها.
- لا تُستخدم بيانات المستخدم لتدريب أي نموذج.
- كل مستخدم يرى محادثاته ومشاريعه فقط (مفروض على مستوى الاستعلام ومُختبر).
- تحذير ظاهر في صفحة الدخول وفي بداية كل محادثة: لا ترفع معلومات حساسة في النسخة التجريبية.
- أي تحليل ذي طابع قانوني يُذيَّل تلقائياً بتحذير: مسوّدة للمراجعة البشرية وليست استشارة نهائية.

## حدود النسخة الحالية وخارطة التوسعة

**غير مدعوم اليوم (ويُبلَّغ المستخدم به صراحةً):**

- OCR للملفات الممسوحة ضوئياً.
- صيغة DOC القديمة و XLS/XLSX.
- الصفحات التي تتطلب تسجيل دخول أو اشتراكاً.
- تشغيل Python داخل Sandbox.
- تنفيذ إجراءات داخل المتصفح (نقر، ملء نماذج، رفع ملفات).

**نقاط التوسعة الجاهزة في الكود:**

| التوسعة                      | نقطة البداية                                                     |
| ---------------------------- | ---------------------------------------------------------------- |
| تصفح تفاعلي (نقر/نماذج/تنقل) | `BrowserAction` و `performBrowserActions` في `lib/web-reader.ts` |
| تشغيل Python                 | `SandboxRequest.runtime` + صورة حاوية جديدة في `docker/`         |
| OCR                          | `parsePdf` يعيد `needsOcr` — أضف مزوّد OCR عند هذه النقطة        |
| تخزين سحابي للملفات          | `storeFile` / `readStoredFile` في `lib/storage.ts`               |
| مزوّد نموذج جديد             | نفّذ واجهة `LlmProvider` في `lib/llm.ts`                         |
| تنفيذ إجراء بعد الموافقة     | `POST /api/approvals/:id` — اربط التنفيذ بحالة `approved`        |
| حد معدل موزّع                | `rateLimit` في `lib/http.ts`                                     |
